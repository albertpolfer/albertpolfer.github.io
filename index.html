Un despacho sin infraestructura propia en la nube pasa a trabajar íntegramente sobre escritorios remotos en Azure, con su dominio, sus perfiles y su unidad de red de siempre.

A practice with no cloud infrastructure moves entirely onto Azure remote desktops, keeping its domain, its profiles and the network drive everyone was used to.

Qué se hizo

  • Bosque nuevo sobre un controlador de dominio desplegado en Azure, promovido automáticamente por la extensión de la máquina.
  • Entra Connect con sincronización de hash de contraseña: unos 50 usuarios híbridos repartidos en OUs de sincronización y de AVD.
  • 50 session hosts con Hybrid Azure AD Join, Microsoft 365, Adobe Reader y FSLogix en la imagen.
  • Azure Files autenticado con Entra Kerberos y la unidad de red montada sola al iniciar sesión, sin pedir credenciales.
  • Red, Key Vault, cuenta de almacenamiento, dominio y hosts definidos en plantillas Bicep modulares, validadas con what-if antes de cada despliegue.
  • Plan de escalado que desaloja los hosts sin sesión activa.

Lo que costó de verdad

  • Las cuotas de vCPU en Azure van también por familia de máquina, no solo por región: la familia se agotó antes que el total. Y desalojar una máquina no libera cuota, hay que eliminarla.
  • El bosque interno y el dominio de correo no coincidían, así que los usuarios llevan un sufijo UPN añadido al bosque para que el soft-match empareje sin crear duplicados.
  • Montar Azure Files desde Run Command como SYSTEM se queda colgado; hay que hacerlo en sesión interactiva.

What was done

  • New forest on a domain controller deployed in Azure, promoted automatically by the VM extension.
  • Entra Connect with password hash sync: around 50 hybrid users across sync and AVD OUs.
  • 50 session hosts with Hybrid Azure AD Join, Microsoft 365, Adobe Reader and FSLogix baked in.
  • Azure Files authenticated with Entra Kerberos, with the network drive mounting itself at sign-in without prompting.
  • Network, Key Vault, storage account, domain and hosts defined in modular Bicep templates, validated with what-if before each deployment.
  • Scaling plan that deallocates hosts with no active session.

The parts that actually hurt

  • Azure vCPU quota is per VM family as well as per region — the family ran out before the regional total. And deallocating a VM does not release quota; it has to be deleted.
  • The internal forest and the mail domain did not match, so users carry a UPN suffix added to the forest so soft-match pairs them without creating duplicates.
  • Mounting Azure Files from Run Command as SYSTEM hangs; it has to be done in an interactive session.

Qué se hizo

  • Español como idioma de sistema y de la pantalla de inicio de sesión en 48 hosts, aplicado como SYSTEM vía Run Command.
  • Instalación silenciosa del software del sector, un instalador NSIS, con sus tres DSN ODBC contra SQL Server.
  • Orquestador que recorre la flota por lotes, con el host de referencia blindado para no tocarlo.

Cómo se hizo sin romper nada

  • Piloto en un solo host antes que nada, y validación en frío: reiniciar y comprobar que el idioma persiste, incluido el mensaje de error del sistema.
  • Verificación forense contra el host de referencia. La instalación silenciosa dejaba 3 ficheros frente a 28, lo que parecía un fallo. Comparando recuentos y marcas de tiempo se vio que la aplicación real —461 ficheros, 959 MB— estaba idéntica en ambos, y que los 25 restantes eran datos que el programa copia de la red la primera vez que se abre.
  • Prueba en seco del orquestador sobre los 48 hosts antes de lanzarlo de verdad.

What was done

  • Spanish as the system and sign-in screen language on 48 hosts, applied as SYSTEM via Run Command.
  • Silent install of the sector application, an NSIS installer, with its three ODBC DSNs against SQL Server.
  • An orchestrator that walks the fleet in batches, with the reference host guarded so it is never touched.

How it was done without breaking anything

  • Pilot on a single host first, then cold validation: reboot and confirm the language persists, right down to the system error message.
  • Forensic verification against the reference host. The silent install left 3 files against 28, which looked like a failure. Comparing counts and timestamps showed the real application — 461 files, 959 MB — was identical on both, and the remaining 25 were runtime data the program copies from the network the first time it opens.
  • Dry run of the orchestrator across all 48 hosts before firing it for real.

Qué se hizo

  • Suite de scripts en PowerShell que extrae el inventario del tenant por bloques: identidad y grupos, Teams y telefonía, licencias, permisos.
  • Registro de aplicación con consentimiento de administrador para poder ejecutarlo desatendido por token, sin pedir sesión en cada bloque.
  • Ruta alternativa para los bloques que no necesitan Microsoft Graph, de modo que se pueda empezar a auditar el mismo día aunque el consentimiento tarde en aprobarse.

Detalle útil

  • Cinco de los diez bloques salían adelante sin Graph, apoyándose solo en los módulos de Teams. Eso permitió entregar la mitad del inventario mientras el consentimiento estaba en cola.

What was done

  • A PowerShell script suite that extracts the tenant inventory in blocks: identity and groups, Teams and voice, licensing, permissions.
  • App registration with admin consent so it could run unattended by token, without prompting for sign-in on every block.
  • A fallback path for the blocks that do not need Microsoft Graph, so auditing could start the same day even while consent was pending.

Useful detail

  • Five of the ten blocks ran without Graph at all, relying only on the Teams modules. That made it possible to deliver half the inventory while consent sat in the approval queue.
